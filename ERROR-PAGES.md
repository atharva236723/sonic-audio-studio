# Error pages

The static bundle includes 400, 403, 404, 500, 502 and 503 pages in English, Spanish, Japanese, French, German, Portuguese, Korean and Italian. They share the site's navigation, light/dark styles, reduced-motion support and localized recovery links. All are marked noindex and excluded from sitemap.xml.

Run build-i18n.cjs to regenerate content, sitemap.xml, robots.txt and error pages. It invokes build-errors.cjs automatically.

The local preview serves missing routes as HTTP 404, malformed paths as 400, forbidden paths as 403, and filesystem failures as 500. Direct error-page URLs return the matching HTTP status. A 503 includes Retry-After: 60. Localized paths use the corresponding localized error document. The server keeps the requested URL, avoiding redirects that could conceal the failure status.

For production, configure the hosting provider's error-document mapping to serve /404.html for missing routes and /500.html, /502.html and /503.html for those server failures, preserving the actual error status. A static HTML bundle cannot intercept errors generated by the host itself. Do not add blanket homepage rewrites for missing URLs. Prefer the matching language document when the host supports locale-specific rules. These documents are supplied but no production host settings or deployment were changed.
